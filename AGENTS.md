# Math Happens — project notes

- Stack: Next.js 16 App Router (`src/app`), React 19, TypeScript 5.9, Tailwind CSS 4 (theme tokens in `src/app/globals.css`), Vitest 4.
- Verify changes with `npm run check` (typecheck → lint → test → build). Individual steps: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
- `src/lib/**` is framework-free TypeScript with Vitest coverage; keep React out of it. UI lives in `src/components`, hooks in `src/hooks`.
- Test files are `src/**/*.test.ts`. Engine tests verify generated answers through `src/lib/engine/testing/independent-arithmetic.ts` (BigInt on display strings) rather than the `Rational` module — keep that independence when adding generators.
- The session reducer (`src/lib/session/reducer.ts`) must stay pure: randomness comes from the seeded RNG state stored in `SessionState`, and time arrives via action payloads (`now` monotonic ms, `wallClock` epoch ms).
- ESLint 9 is pinned because `eslint-config-next`'s `eslint-plugin-react` dependency breaks on ESLint 10. Dependencies are pinned to versions published at least a week before adoption.
- Phase 2 modules: `lib/choice` (distractor models + open-answer classification share the same mistake catalogue — add new mistakes in `distractors.ts` and both benefit), `lib/analysis` (facets/features/weakness), `lib/adaptive/plan.ts`, `lib/review/schedule.ts`, `lib/techniques/library.ts` (each technique needs `applies` + an exact `explain`; tests assert every explanation reaches the true answer), `lib/storage/indexeddb.ts` + `transfer.ts`.
- Advanced settings (`lib/engine/advanced.ts`) are part of `TrainerSettings` and inert while `advanced.enabled` is false — any change here must keep the default question stream bit-for-bit identical (`src/lib/engine/ranged.test.ts` and `advancedSession.test.ts` assert this). When enabled, the operation/format percentages *replace* `settings.operations`/`numberTypes`; read them through `effectiveOperations`/`effectiveNumberTypes` rather than the raw arrays.
- Range-driven generators live in `lib/engine/generators/ranged.ts` and must never hang or throw on a nonsensical range: every bound is clamped and ordered, and the retry loops are bounded with a valid degenerate fallback. They use `-custom` variants so analysis keeps them separate from the difficulty tiers (add a `FACET_LABELS` entry for any new one).
- `lib/session/mix.ts` apportions the percentages. Fixed-length sessions get a `mixSchedule` built once in `createSession` from the session RNG (so the session stays reproducible, and the RNG is left untouched when no schedule is needed); open-ended and timed sessions sample by weight. Operation and format shares are apportioned independently so formats spread across operations.
- `validateAdvanced` returns per-field issues shown beside the field; `validateSettings` only adds a single pointer line so the same text does not appear twice.
- Attempts store the expression, not the operands; use `lib/analysis/reconstruct.ts` (`questionFromAttempt`) when you need the `Question` back.
- Clearing: `repositories.clearHistory()` drops sessions/attempts/review and keeps settings plus the migration marker; `clearAll()` drops everything. Both purge the configured `mirrors` (localStorage) as well, otherwise the next `migrateFromWebStorage` copies deleted records back in.
- Browser data is per origin, so the same app on port 3000 and 3210 has separate IndexedDB stores. Check the port before concluding history is missing.
- Legacy records: attempts/sessions from Phase 1 lack `answerFormat`/`choice`/`errorTag`; `normalizeAttempt`/`normalizeSummary` in `repositories.ts` fill defaults on read. Never require those fields when reading stored data directly.
- Pages read history through `useHistory()`; use its `loadedAt` as "now" in analysis so renders stay pure (the React Compiler lint forbids `Date.now()` in render). The same lint also forbids calling `setState` synchronously in an effect body — derive status in render instead (see `useSessionComparison`).
- Multiple choice: the verdict is rendered synchronously by the reducer (`reveal: { selectedIndex, startedAt }`); the only delay is the auto-advance hold in `useSession` (`REVEAL_MS`, 300 ms correct / 1100 ms incorrect). Any key or a click in the question area cuts the hold short via `skipReveal`, which is ignored for `SKIP_GRACE_MS` after `startedAt` so a double-click cannot blow past a question. Skip handlers read `revealing` from the render they were created in, so the click/key that produced a verdict can never also skip it. Double submission is prevented by the reducer, not the UI: `choose` and `submit` are no-ops while `reveal !== null`.
- Session results are compared with earlier ones in `lib/analysis/comparison.ts`: `comparabilityKey` decides what counts as "the same test" (Improve vs Train, mode, the length setting the mode actually uses, difficulty, answer format, effective operations/number types in canonical order, and the advanced ranges/mixes in use). The baseline is matching sessions that ended *before* the one shown, so a session reopened from history always shows the same figures. Completion time is only compared for untimed sessions with a question limit that reached it (`completionTimeMs`); timed and open-ended sessions fall back to correct/min.
- `coerceSettings` drops `plan` (a preference must never carry one), so stored sessions are read with `coerceSessionSettings`, which keeps it — without it an Improve session reads back as ordinary practice and gets compared with Train sessions.
- `OPERATIONS` is `ARITHMETIC_OPERATIONS` plus `finance`. Anything that does column arithmetic (generators, `computeAnswer`, `buildMeta`, `operandRanges`, the independent test arithmetic) takes `ArithmeticOperation`; `isArithmetic()` narrows. Finance is deliberately **not** in `DEFAULT_SETTINGS.operations` or the default `operationMix`, so default practice and stored setups are untouched until it is ticked.
- Finance questions are word problems: `lib/engine/finance.ts` holds the settings (12 family shares, value style, exact/estimate, rounding, amount range) and `lib/engine/generators/finance.ts` holds the templates. A question is fully described by `meta.finance` (`{ subtype, mode, inputs, places, estimate }`); `renderFinance` derives prompt, answer, unit, instruction and explanation from it, so stored attempts can be re-explained later and an improved explanation applies retroactively. Templates return `explain: (final) => string[]` — the renderer passes the *rounded* answer in, which is what keeps explanations honest.
- Finance answers carry an `AnswerUnit` (`lib/engine/units.ts`). `answerDisplay` is the single place that renders a value as an answer (used by the choice set, the attempt record and feedback), `stripUnit` in `answer/validate.ts` lets the unit be typed or omitted without ever accepting the wrong unit, and `question.tolerance` is what makes estimation questions gradeable. Add a new unit → update `UNIT_HINTS`, `unitSuffix`, `formatWithUnit` and `UNIT_MARKERS` together.
- `buildChoiceSet` rounds every option to `question.answerPlaces` and dedupes by *displayed text*, so two values that round to the same thing can never both appear. Any new question type with rounding gets that for free.
- Finance facets are `fin-<subtype>` (one per family) — add a `FACET_LABELS` entry for a new family or weakness analysis will fall back to a generic label. Targeted practice generates finance families directly (`financeSubtypeOfFacet`) instead of rejection-sampling.
- `computeMetrics` records `medianCorrectResponseMs` (median over correct answers only, so rushing wrong answers cannot flatter speed). It is optional on `SessionMetrics`: sessions recorded before it existed have no value and must be treated as unknown, never zero.
- Browser checks live in `/tmp/mh-verify` as throwaway Playwright scripts (`flow.mjs`, `finance.mjs`, `legacy.mjs`, `timed.mjs`, `improve.mjs`) run against `next dev`; nothing browser-related lives in the repo. Note that `innerText` applies `text-transform`, so uppercase headings need case-insensitive matching.
